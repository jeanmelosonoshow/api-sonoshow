Documentação oficial

API de integração SonoShow

Consulte a estrutura de usuários e as vendas disponibilizadas para integração com sistemas autorizados. Todas as respostas usam JSON e o acesso é protegido por token.

https://sua-api.vercel.app

Fluxo de uso

Comece em três etapas

A integração usa HTTP sobre HTTPS, autenticação Bearer e conteúdo JSON. Não é necessário instalar um SDK específico.

1

Solicite o token

Envie a solicitação ao administrador e informe qual sistema consumirá a API.

2

Envie o cabeçalho

Inclua Authorization: Bearer SEU_TOKEN em todas as requisições.

3

Consuma os dados

Consulte usuários por GET e filtre vendas por período e códigos de produto.

Segurança

Autenticação

A API usa um Bearer Token individual, enviado no cabeçalho HTTP. Trate esse token como uma senha e mantenha-o somente no servidor que fará a integração.

Como obter acesso

Solicite o token ao administrador Jean Melo pelo e-mail jean.melo@sonoshow.com.br. Informe a empresa, o sistema consumidor e o responsável técnico.

Cabeçalho obrigatório
Authorization: Bearer SEU_TOKEN_DE_ACESSO
Nunca envie o token na URL. Não publique o valor em repositórios, logs, código executado no navegador ou mensagens sem proteção.

Estrutura organizacional

Usuários

GET/usuariosRetorna todos os usuários disponíveis

Use este endpoint para obter diretores, supervisores, gerentes e vendedores, incluindo sua filial e relação de responsabilidade.

Exemplo de requisição

cURL
curl --request GET \
  --url 'https://sua-api.vercel.app/usuarios' \
  --header 'Authorization: Bearer SEU_TOKEN_DE_ACESSO'

Resposta de sucesso

HTTP 200 · application/json
{

Movimento comercial

Vendas

POST/vendasFiltra vendas por produtos e período

Envie os códigos dos produtos no corpo da requisição. O período pode ser informado na URL para restringir o conjunto retornado.

Parâmetros da URL

ParâmetroObrigatoriedadeFormatoDescrição
date_startOpcionalYYYY-MM-DD HH:MM:SSInício inclusivo do período. Deve respeitar a data inicial disponibilizada.
date_endOpcionalYYYY-MM-DD HH:MM:SSFim inclusivo do período.
Codifique o espaço da data como %20. Exemplo: 2026-09-01%2000:00:00. Se o início não for informado, a consulta considera somente o dia atual quando a fonte direta estiver ativa.

Corpo da requisição

JSON obrigatório
{
  "produtos": ["001", "002"]
}

Os códigos devem ser textos. É possível enviar até 2.000 produtos por requisição. Uma lista vazia retorna { "vendas": [] }.

Exemplo completo

cURL
curl --request POST \
  --url 'https://sua-api.vercel.app/vendas?date_start=2026-09-01%2000:00:00&date_end=2026-09-30%2023:59:59' \
  --header 'Authorization: Bearer SEU_TOKEN_DE_ACESSO' \
  --header 'Content-Type: application/json' \
  --data '{"produtos":["001","002"]}'

Resposta de sucesso

HTTP 200 · application/json
{

Disponibilidade

Status da API

GET/healthConfirma que o serviço está ativo

Use esta rota para verificar autenticação e disponibilidade básica do processo. Uma resposta positiva não confirma, por si só, a atualização dos dados.

cURL
curl --request GET \
  --url 'https://sua-api.vercel.app/health' \
  --header 'Authorization: Bearer SEU_TOKEN_DE_ACESSO'
HTTP 200
{
  "status": "ok",
  "mode": 2
}

Diagnóstico

Respostas de erro

Erros são retornados em JSON com um código estável e uma mensagem explicativa.

Formato
{
  "error": "UNAUTHORIZED",
  "message": "Token invalido."
}
400 Bad Request

JSON, filtro de produtos ou período inválido.

401 Unauthorized

Token ausente, inválido ou enviado incorretamente.

405 Method Not Allowed

Método HTTP diferente do definido para a rota.

413 Payload Too Large

Corpo enviado ou resultado acima do limite permitido.

415 Unsupported Media Type

Requisição POST sem Content-Type: application/json.

503 Service Unavailable

Dados temporariamente indisponíveis ou aguardando atualização.

Boas práticas

RecomendaçãoComo aplicar
Proteja o tokenArmazene-o como segredo ou variável de ambiente no servidor consumidor.
Use HTTPSFaça chamadas somente para a URL oficial fornecida pelo administrador.
Envie códigos como textoUse "001", preservando zeros à esquerda.
Consulte períodos objetivosInforme date_start e date_end para reduzir o volume da resposta.
Trate indisponibilidadeEm erros 503, aguarde antes de tentar novamente e use intervalo progressivo entre tentativas.
Não presuma unicidade localAo reprocessar um período, substitua os dados desse período conforme a regra da integração.
